Origen de datos
Nombre del reporte i Nombre exacto del reporte configurado en la plataforma SIESA Connekta. Se envía como parámetro descripcion en la URL de la API REST y debe coincidir con el nombre registrado en SIESA Cloud.
Parámetros i Pares clave = valor que se envían al reporte, separados por | (pipe). Soporta placeholders de fecha que se resuelven en cada ejecución y se pueden mezclar con valores fijos.
ClaveValor

Placeholders disponibles: {hoy}, {hoy-N}, {hoy+N}, {inicio_mes}, {fin_mes}, {inicio_mes-N}, {fin_mes-N}

Paginación i Si está activado, el sistema solicita los datos en páginas de 100 registros hasta obtener todos los resultados. Actívalo cuando el reporte retorna más de 100 registros.
Activada — 100 registros por página
Configuración del flujo — Clientes / Proveedores
Mapeo de campos i Renombra los campos de SIESA al nombre canónico del sistema. Obligatorios para terceros: identificacion, nombre, sucursal. Opcionales: direccion, telefono, email, ciudad, departamento, pais, codigo_postal.
Campo SIESAAlias canónico
Valores fijos i Valores constantes que se inyectan a todos los registros. Ejemplo: pais siempre es 'Colombia' para todos los terceros de este cliente.
CampoValor
Jerarquía de sucursales i Si está activado, el sistema procesa primero la sucursal padre (como empresa principal) y luego las demás como contactos hijos vinculados a ella. Si está desactivado, cada sucursal se crea como contacto independiente.
Activada
Sucursal padre i Código de la sucursal que se considera casa matriz. Solo tiene efecto si la jerarquía está activada. Las demás sucursales se crean como contactos hijos de esta. El valor más común es 001.

sucursal_padre

País i ID del país en Odoo (res.country). Se asigna a todos los terceros creados por este flujo. 49 = Colombia. Consultar en Odoo: Contactos → Configuración → Países.

country_id

Tipo de identificación i ID del tipo de documento en Odoo (l10n_latam.identification.type). 5 = NIT, 3 = Cédula de ciudadanía, 4 = Cédula de extranjería.

identification_type_id

Lógica de variables y funciones i Reglas condicionales que transforman valores después del mapeo. Hay dos modos: reglas simples (si el campo X vale Y, el campo Z recibe W) y funciones del catálogo para lógica más compleja. Se ejecutan DESPUÉS del mapeo de campos.
No hay reglas configuradas
